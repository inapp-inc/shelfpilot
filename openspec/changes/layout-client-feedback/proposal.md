# Proposal: Layout client feedback — envelope, autogen, UX & review workflow

**Status:** Approved / Implemented — draw UX + dual-face 3D 2026-07-27

**Source:** Client presentation feedback (2026-07-21), following `layout-dimensions-rotation-shelf-bays`.

**Methodology reference:** [Docs/Standard Methods for Store Layout Design.md](../../Docs/Standard%20Methods%20for%20Store%20Layout%20Design.md) — industry pattern is **measurement-driven design with graphical visualization layered on top**; this change closes gaps where the editor behaved like draw-first / infer-measurements-later.

## Summary

Seven client-requested improvements to the layout editor, autogenerate behaviour, canvas UX, properties panel, and approval workflow — aligned with standard retail layout practice: enter real-world dimensions first, auto-scale the canvas, place standard fixture templates, validate compliance, then iterate visually and review in 2D/3D.

## Industry methodology alignment

| Standard method | ShelfPilot behaviour (this change) |
|-----------------|-----------------------------------|
| **Measurement-first, draw-second** | Layout create captures store W×D; **store envelope** persists separately from the drawn **fixture polygon** (CF-01). Meter bar shows both in metres. |
| **Grid-based scaled canvas** | Canvas auto-scales to entered dimensions; **fit to view** on open/apply (CF-03). |
| **Fixture templates / libraries** | Palette + Smart Generate use typed templates (`shelf`, `gondola`, `storage`, `rack`); category mix assigns **fixture type** per category, not one generic block (CF-02). |
| **Adjacency & flow planning** | Drawn fixture zone defines where fixtures may live; autogen respects polygon containment; **Focus by category** pans/zooms to mapped zones (CF-02, CF-03). |
| **Iterative what-if adjustment** | **Edit area** — drag polygon vertices/edges after apply; drag/rotate fixtures on scaled grid (CF-06). |
| **Compliance-driven constraints** | Aisle min-width validation; autogen **zero tolerance** for shelves/aisles outside fixture polygon; violations flagged, not silently persisted (CF-02). |
| **3D walkthrough for validation** | 2D measured layout remains source of truth; existing Orbit/Walk 3D unchanged — used for stakeholder review after 2D layout (out of scope for this change). |
| **Reuse / master layouts** | Version snapshots + review workflow support clone-and-adjust chains; template store types via vertical config (CF-07; partial — full master-clone UX is follow-on). |

**Design principle (from standard methods):** Designers enter dimensions and select standard fixtures; the system renders a scaled visual canvas — not freehand shapes with inferred measurements.

## Deliverables

### 1. Store envelope + fixture zone (dual boundary)

- Preserve **store envelope** (`storeEnvelope`: rect from layout create or explicit outer bounds) separately from **fixture polygon**.
- On Apply area: save drawn polygon as fixture zone; render **outer envelope** (full store W×D) in a **secondary colour** (e.g. slate dashed) and **inner polygon** in existing crimson fixture-zone style.
- Meter bar shows both: `Store 20×15 m · Fixture zone 14×10 m`.
- *Aligns with:* measurement-first workflow — numeric store dimensions are authoritative; drawn zone is a subset for fixture placement.

### 2. Strict autogen + category fixture types

- Packer/autogen: **zero tolerance** for shelves/aisles outside polygon; increase post-gen validation and skip reporting.
- **Category → fixture type** mapping in Smart Generate (and optional manual override): e.g. Fresh Produce → `storage`, Grocery → `gondola`, default → `shelf`.
- Palette remains available for manual placement of all types.
- *Aligns with:* fixture template libraries + compliance-driven constraints.

### 3. Viewport-fit editor + focus zoom

- Editor layout: canvas + side rail **fit within viewport** (no document body scroll for rail tabs).
- **Fit to view** on open / after Apply (scale canvas to available height).
- **Focus control** in meter bar: dropdown of categories (mapped on layout) + “Selection” → pan/zoom canvas to bounding box of shelves/aisles for that category.
- *Aligns with:* grid-based scaled canvas + adjacency/flow planning.

### 4. Shelf name in Properties

- Properties panel (shelf selected): show **editable name/label**, display number, type, dimensions (read-only summary).
- *Aligns with:* measured fixture entities with human-readable identity (not anonymous drawn shapes).

### 5. Side rail tab alignment fix

- Fix CSS/layout so tab strip stays fixed width/aligned; merch panel scrolls inside `.editor-rail-body` only.

### 6. Resizable polygon floor area

- **Edit area** mode: select polygon → drag vertices and edge midpoints to reshape; Apply/Save commits.
- **Draw area** mode: click to place corners with **rubber-band line preview** from last point to cursor; click start point (green) or **Apply area** to close.
- Optional: axis-aligned bounding resize handles on polygon AABB for quick adjust.
- *Aligns with:* iterative what-if adjustment on a measurement-backed canvas.

### 6b. Dual-face gondola + mixed-orientation 3D

- Double-sided shelves render **Face A (A1)** and **Face B (A2)** on opposite depth sides in 3D with open merchandising (not closed backs).
- **Vertical aisles** in 3D use correct footprint (length along Y / Z axis), fixing mixed-orientation layouts.
- 2D canvas shows gondola spine divider on dual-face units; vertical aisle dimensions label run × width correctly.
- Autogen packs **gondola runways**: walk aisle → double-sided shelf row (A1/A2 opposite) → walk aisle.
- *Aligns with:* fixture template libraries + 3D walkthrough validation.

### 7. Review workflow gating + rejection comments

- **Reject** opens modal requiring **comment**; persist `reviewComment` (+ `reviewedAt`, `reviewedBy`) on layout.
- Designer sees rejection comment when status = `rejected`.
- **Submit for review**: visible only when `draft` or `rejected`, or when layout **dirty since last submit** (content hash / `updatedAt` vs last version snapshot).
- **Approve / Reject**: visible only when `in_review` and approver has not acted on **current submitted version**; after approve/reject, hidden until designer edits and resubmits.
- *Aligns with:* stakeholder review before 3D walkthrough / rollout.

## Success criteria

- Apply irregular polygon inside 20×15 m store → **outer envelope** visible in second colour; fixture zone unchanged semantically (**measurement-first**).
- Generate on L-shaped polygon → **0** shelves outside dashed line; produce category rows use **storage** type where configured (**templates + compliance**).
- Open layout editor on laptop → **no body scroll** to reach Merchandising tabs; Focus → “Fresh Produce” zooms to those shelves (**scaled canvas + flow focus**).
- Select shelf → Properties shows **editable name** + face label summary (see `shelf-face-letter-number-labels`).
- Merchandising tab: tabs stay aligned when scrolling product list.
- Edit area: drag polygon vertex after apply; save persists (**iterative adjustment**).
- Reject requires comment; Submit hidden after submit until edit; Approve hidden after approve until resubmit (**review cycle**).
- Duplicate an approved layout → new **draft** copy opens with same fixtures and envelope (**master reuse**).
- Draw floor area: click corners with **live line preview**; close on start point or Apply (**boundary tracing**).
- Generate mixed orientation → vertical aisles visible in 2D and 3D; dual-face shelves show **A1/A2** products on opposite sides (**3D validation**).

## Non-goals

- Multi-floor stores / multiple polygons per layout (v1: one fixture polygon + one envelope).
- Full BIM/CAD polygon boolean ops (not a general CAD replacement — see standard methods doc).
- Email notifications on reject (comment stored in app only).
- Designing directly in 3D (2D measured layout remains authoritative per industry pattern).
